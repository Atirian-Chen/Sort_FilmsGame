# Film Sort Event Taxonomy

## 1. Scope

Film Sort uses an anonymous event system for product analytics, funnel analysis, template performance analysis, and later experiment analysis. The current implementation records anonymous session events in Supabase and reads them back for public metrics and the private analytics dashboard.

This taxonomy is based on repository code, `supabase_schema.sql`, the current analytics dashboard logic, and a read-only Supabase sample check. It does not claim any unverified business result or experiment outcome.

The event system should not collect phone numbers, email addresses, exact identity data, IP addresses, raw user agents, full custom movie lists, or complete rankings unless a separate explicit privacy review adds a narrow exception. The current `sanitize_payload` logic blocks common sensitive keys before analytics payloads are written.

## 6. Analysis Capability Matrix

| Analysis Question | Can Answer Now? | Required Data | Current Gap | Next Action |
|---|---|---|---|---|
| Visit-to-start conversion | Partially | `visit`, `sorting_started`, `session_id`, `created_at` | Historical instrumentation changes and source-specific `track_once` behavior can affect denominator. | Use current-instrumentation windows and document denominator. |
| Start-to-completion conversion | Yes | `sorting_started`, `ranking_completed`, `session_id`, `created_at` | Sessions without `session_id` or legacy rows may reduce precision. | Run session funnel SQL and null checks. |
| Completion-to-share/download conversion | Yes | `ranking_completed`, `share_copied`, `poster_downloaded`, `session_id` | Share/download may happen multiple times per session; event vs session denominator must be explicit. | Report both event counts and session counts. |
| Different template performance | Partially | `template_id`, `list_id`, `mode`, funnel events | Some flows use `mode` or `challenge_id` instead of `template_id`. | Normalize list identity in analysis view. |
| Different movie-count performance | Partially | `payload.list_size` / aliases, completion/start events | Missing on some events or historical rows. | Use started/completed rows with non-null `list_size`. |
| Different device performance | Partially | `payload.device_type`, funnel events | Device is coarse and may be `unknown`; not top-level. | Use as directional split only. |
| Different channel performance | Partially | `source_channel`, `payload.source`, UTM fields | Query-param based attribution only; no referrer domain. | Use current source/UTM fields, add sanitized referrer later if needed. |
| Sorting abandonment position | No | Progress or abandonment event, comparison milestones, elapsed time | No explicit `ranking_abandoned`; `comparison_made` alone is incomplete. | Add `ranking_progress` and/or `ranking_abandoned` in Step 2. |
| User retention | No | Stable anonymous user ID across sessions/days | Only session ID exists. | Add privacy-reviewed anonymous user ID only if retention is required. |
| A/B experiment effect | Partially | `experiment_exposed`, variant, funnel events, enough sample size | v3.3 adds true exposure events, but historical experiments lack this denominator and current experiments may be paused. | Use exposed sessions for new experiments; keep historical assigned-session views diagnostic only. |

## 7. Data Privacy and Safety

- Use anonymous analysis by default. `session_id` is for session stitching only and must be masked or hashed in exports.
- Do not export raw Supabase URL, keys, admin tokens, service-role credentials, raw session IDs, contact fields, IP addresses, exact geolocation, raw referrer query strings, or complete custom rankings.
- Sanitized samples may include event names, timestamps, top-level non-sensitive identifiers, masked sessions, and non-sensitive payload fields required for analytics checks.
- Test traffic should be separated in Step 2 with an explicit `is_internal_test` flag or a documented source/session convention. Current data has no dedicated test-traffic field, so any filtering is heuristic.
- Mock or sample data must be clearly labeled as sample data and never described as production traffic.
