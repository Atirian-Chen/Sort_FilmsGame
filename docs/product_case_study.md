# Sort_FilmsGame 产品案例复盘

## 1. 产品概览

Sort_FilmsGame 是一个影视偏好排序 Web App，帮助用户通过连续 1v1 二选一取舍，生成自己的个性化电影审美榜单。

产品把“手动整理电影 Top 榜”拆成连续的轻量选择：用户不用一次性想清完整顺序，只需要在两部电影之间做判断，最后得到个人电影审美榜单、结果海报和可分享链接。

## 2. 目标用户

- 影迷 / 豆瓣用户
- 想整理个人电影 Top 榜的用户
- 社交平台内容创作者
- 喜欢通过分享海报表达个人审美的用户

## 3. 用户痛点

- 手动整理电影榜单成本高，尤其是候选电影较多时，很难直接排出完整顺序。
- 传统打分不能很好表达相对偏好，两个同分电影之间仍然需要取舍。
- 用户需要一个更有趣、更轻量的方式生成个人审美榜。
- 生成结果需要适合社交分享，而不是只能停留在列表文本。

## 4. 核心用户路径

访问产品 -> 选择片单 -> 1v1 取舍排序 -> 查看榜单结果 -> 生成海报 / 二维码 -> 分享

## 5. 核心功能

- 1v1 偏好排序
- 豆瓣高分片单 / 导演作品 / 自定义片单
- 豆瓣已看导入
- 结果海报
- 二维码分享
- 移动端适配
- 匿名行为埋点
- 后台数据看板 v2

## 6. 指标体系

- 激活指标：`start_rate = sorting_started / visit`
- 核心参与指标：`completion_rate = ranking_completed / sorting_started`、`average_comparisons`
- 分享指标：`share_rate = share_copied / ranking_completed`、`poster_download_rate = poster_downloaded / ranking_completed`
- 内容 / 片单指标：按 `list_id / template_id / mode` 分析完成表现
- 增长指标：按 `source / utm_source / utm_medium / utm_campaign` 分析渠道转化
- 实验指标：按 `experiment_id / variant_id` 比较开始率和完成率

## 7. 当前洞察模板

- 最大流失通常发生在“访问产品 -> 开始整理”之间，说明用户是否理解产品价值、是否看到合适片单入口、是否觉得开始成本可接受，是当前最优先的增长问题。
- 如果完成率明显高于开始率，说明核心玩法对已开始用户有效，但首屏认知和开始成本需要优化。
- 如果海报下载率高于复制分享率，说明视觉化结果比纯链接分享更有吸引力，后续可以优先迭代多海报模板和社交平台适配。
- 如果某些片单的完成率显著更高，说明“片单主题”本身会影响参与意愿，可以把高完成片单作为默认推荐或投放素材。

## 8. 迭代计划

P0：提升访问到开始整理转化

- 优化首屏价值表达。
- 默认推荐快速片单。
- 展示示例结果海报。
- 增加预计耗时和步骤说明。
- 用 `home_layout_order_v1` 实验对比“快速开始片单前置”和“豆瓣已看主推前置”对开始率的影响；后续再单独开启 CTA 文案实验。

P1：提升完成率

- 增强进度条反馈。
- 增加快速模式 / 精细模式。
- 支持中途保存。
- 增加疲劳点提示。
- 分析平均取舍次数和中途退出点，判断是否需要减少默认整理规模。

P2：提升分享率和传播

- 多海报模板。
- 审美关键词。
- 分享挑战同一片单。
- 渠道追踪。
- 用渠道转化数据判断小红书、豆瓣、微信群等渠道的真实转化质量。

## 9. 产品收获

- 学会从真实用户行为中定位问题，而不是只凭主观感觉决定功能优先级。
- 学会通过漏斗判断优先级：如果开始率低于完成率，优先优化首屏认知和开始成本，而不是继续堆复杂功能。
- 理解为什么不是先加功能，而是先优化最大流失环节：增长问题需要先找到瓶颈，再选择最小可验证的实验。
- 学会用匿名埋点和后台看板支撑产品迭代，在不采集姓名、联系方式、IP 等敏感信息的前提下，仍然建立可分析、可复盘的数据闭环。
